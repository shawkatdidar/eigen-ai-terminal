- **HyLo (ArXiv 2604.24715): pretrained Transformer upcycling → hybrid MLA + Mamba2, 32× context extension** — Converts any pretrained Transformer's attention heads into hybrid MLA (Multi-head Latent Attention — compresses KV heads into a low-rank latent space, reducing KV-cache memory while preserving expressiveness) + Mamba2/Gated DeltaNet (selective state-space model layers that process sequences in linear time vs. quadratic for standard attention). Results: 32× context extension (128K → 4M+ tokens), KV-cache memory reduced >90%, 2M-token prefill + decoding in vLLM. HyLo-Qwen-1.7B on 10B tokens beats JetNemotron-3-1B trained on 400B tokens across GSM8K, common sense, RULER-64K. → Architectural hybridization outweighs 40× training compute. Any existing model can be converted to 32× longer context without full retraining. Opens a commercial opportunity: upcycling fine-tuned enterprise models to multi-hundred-thousand context without reproducing training runs. ## Today I Learned

### Multi-Cloud as the New Single-Pane Frontier Abstraction

**Why this came up:** OpenAI on Bedrock means enterprises no longer need to choose between frontier model families at the infrastructure level.

**The concept:** Before today, using both Claude and GPT-5.5 in an enterprise required two separate vendor relationships, two DPAs (Data Processing Agreements — contracts governing how vendor handles your data), two billing relationships, and two security reviews. AWS Bedrock was already the abstraction layer for Claude. Adding GPT-5.5 means Bedrock is now the single infrastructure surface for both major frontier families.

This is technically significant because enterprise procurement is the rate-limiter for AI adoption, not capability. A Fortune 500 security team that spent 6 months doing a DPA review with AWS can now access both Claude and GPT-5.5 without additional review. The infrastructure decision (AWS Bedrock) has decoupled from the model decision (Claude vs. GPT-5.5).

The architectural implication: model selection becomes a per-request or per-task decision, not a per-vendor commitment. You can route legal summarization to Claude, code generation to GPT-5.5, and image generation to GPT-Image-2 — all on the same Bedrock account, same compliance framework.

**What changes:** Building multi-model enterprise AI products was previously a compliance coordination problem (multiple vendors, multiple legal agreements). It is now an engineering routing problem (which model for which task). These are different categories of difficulty.

### Quick Glossary

| Term | Meaning |
|------|---------|
| DPA | Data Processing Agreement — contract defining how a vendor handles a customer's data; required for GDPR/CCPA compliance, often takes months to negotiate |
| Bedrock | AWS's managed AI model hosting service — wraps multiple model providers under one AWS contract |
| Upcycling (HyLo) | Converting a pretrained model to a new architecture by replacing select layers, without starting training from scratch |
| MLA | Multi-head Latent Attention — KV-cache compression technique that projects key/value matrices into a smaller latent space, reducing memory at the cost of some expressiveness |
| SSM | Selective State Space Model — processes sequences by maintaining a compressed state vector updated at each token; linear time complexity vs. quadratic for attention |
