## Today I Learned

### Bottleneck migration: when you automate the expensive step, the constraint moves to the adjacent step
**Why this came up:** Fiona Fung's "coding is no longer the bottleneck — verification is."

A software pipeline has stages — *specify → generate → review/verify → integrate → monitor*. Total throughput is set by the slowest stage (the **bottleneck** — the stage with the least spare capacity relative to demand). When AI code generation drops the cost of the *generate* stage toward zero, generation stops being the limiter. Throughput doesn't rise without limit, though: the constraint **migrates** to whatever stage is now slowest — here, *review/verify*. This is why Anthropic's reported response is not "generate even more" but "automate the feedback→PR loop" (**routines**) and "use the model to review against specs and evals" — i.e., invest in the *new* bottleneck, not the old one.

The judgment payoff: when you see a claim that one stage got dramatically cheaper (e.g., "we ship 8× more code"), the right question is not "is generation solved?" but **"which stage is the constraint now, and is it being addressed?"** A 10× cheaper *generate* stage with an unchanged *review* stage yields far less than 10× end-to-end — the verification stage, untouched, caps the gain. That is the difference between a real throughput change and a vanity metric.

### Quick Glossary
| Term | Meaning |
|------|---------|
| Bottleneck | The pipeline stage with the least spare capacity; it sets total throughput. Automating a non-bottleneck stage does not raise output. |
| Verification | Checking that generated output meets the spec and quality bar ("what good looks like") — distinct from generating it. Becomes the constraint once generation is cheap. |
| Routines (Anthropic) | An internal feature that autonomously monitors feedback channels, summarizes them, and opens PRs for human review — automation of the feedback→PR loop. |
| "Bad vs sad" issues | Fung's triage framing — separating genuinely *bad* (broken/incorrect) output from *sad* (suboptimal but acceptable) output, so review effort goes where it matters. |
